# Decision Analysis Playbook

Use when a coding or architecture choice has multiple plausible options and the rationale should survive review.

## Steps

1. State the decision needed, owner, scope, and deadline.
2. List viable alternatives, including doing nothing when realistic.
3. Define criteria before choosing; include user impact, risk, cost, reversibility, maintainability, and verification burden.
4. Weight or rank criteria when tradeoffs are not obvious.
5. Compare alternatives against the same criteria using evidence, assumptions, and uncertainties.
6. Select only after the matrix is visible.
7. Record rationale, weak evidence, follow-up verification, and revisit trigger.

## Output

Produce a decision record with decision, alternatives, criteria, evidence matrix, selected option, rationale, risks, verification burden, and revisit trigger.

## Guardrails

Do not let the chosen option become a retroactive requirement. Downstream verification and validation still need separate evidence.
